# 익스텐션 설계 — 분석 결과를 제품으로

모델링 노트북(`notebooks/modeling.ipynb`) 6장 결론(신호 하나로는 차단 못 한다, 그래도 점수는 쓸모 있다)을 그대로 제품 규칙으로 옮긴 설계 문서. 실제 구현·설치는 [`README.md`](README.md).

## (1) 2단계 파이프라인 — 선택편향에 대한 대응

모델이 배운 채널은 주식 검색어로 잡힌 채널뿐이다. 그런데 익스텐션은 유튜브 전체를 본다. 학습 때 본 적 없는 비경제 채널에까지 모델을 그대로 들이대면, 엉뚱한 채널을 의심하는 오탐이 쏟아진다. 그래서 판단을 두 단계로 나눴다:

```
영상/채널 페이지 → [Stage 0 도메인 게이트] 주식·경제 채널 아니면 통과(판단 안 함)
                          ↓ 주식·경제 채널만
                   [Stage 1 의심 점수] 모델 점수 + 규제어 regex + 신고 이력
                          ↓
        점수·근거 결합 → 차단 / 경고 / 통과
```

Stage 0은 채널 제목·설명·영상 제목에 주식·경제 키워드가 있는지로 1차로 걸러낸다(`reg.js`). 단 '리딩'·'애널리스트'는 주식과 무관한 뜻(독서 리딩, 타로 애널리스트 등)으로도 쓰여 엉뚱한 채널을 끌어들이므로 게이트 키워드에서 뺐다.

## (2) 3층 대응 규칙 — 운영점(목표 precision을 맞추는 threshold)이 숫자 근거

| 층 | 조건 | 동작 | 근거 |
|---|---|---|---|
| 차단 | 규제어 hit **그리고** 모델 점수 ≥ 0.92 | 채널 숨김 + 사유 표시 | precision ≥ 0.9 운영점(recall 0.02 — 극소수만 확실 차단). 모델 단독 차단 금지(H1 기각) — 금융위 규제어라는 법적 근거 동반 시에만 |
| 경고 | 모델 점수 ≥ 0.77 (단독 가능) | 배너 경고 + 금감원 신고센터(fine.fss.or.kr) 링크 | precision ≥ 0.7 운영점(recall 0.10). 미탐 보완층 |
| 통과 | 그 외 | 표시 없음 | 오차단 비용 우선(노트북 1장) |

> 위 0.92/0.77은 노트북 full 36-feature 모델의 운영점이다. 실제 익스텐션은 페이지에서 즉시 읽히는 feature만으로 재학습한 경량 모델이라 threshold가 다르다(README 참고).

**3층 정책 시뮬레이션** — 현 데이터 2,214개 채널에 적용한 규모 감(학습 표본 포함):

```
차단층 75개 | 경고층 229개 | 통과 1,910개   (전체 2,214)
차단층 내 의심 시드 비율: 0.91
```

차단층은 75개로 좁고 그 안의 91%가 의심 시드 → "확실한 것만 막는다"는 설계 의도와 맞는다.

## (3) 구현 구조

- content script: 채널·영상 페이지에서 메타데이터(구독자·영상 수·업로드 시각·설명·고정 댓글)를 뽑아낸다.
- feature 계산: 노트북의 36개 중 페이지에서 바로 계산되는 것만 추려 가볍게 돌린다(전체 댓글 수집은 API 한도 때문에 서버 배치로 미룸).
- 모델 내장: RandomForest 모델을 JSON으로 저장해 익스텐션 안에 넣는다(`model_data.js`, 인터넷 없이 동작). 모델 갱신은 확장 업데이트로 배포.
- 신고 루프: 사용자 '리딩방 신고' 버튼 → 서버 수집 → 정답 라벨 축적 → 재학습. 노트북 6장 3번(라벨 품질)에서 말한 개선 경로와 그대로 이어진다.

## (4) 운영 원칙

- 차단할 땐 이유를 항상 보여준다(어떤 규제어·어떤 신호 때문인지) — 설명 못 하는 차단은 금지.
- 이의제기 버튼으로 오차단 사례를 모아, precision이 떨어지지 않는지 감시하는 지표로 쓴다.
- threshold는 한 번 정하고 끝이 아니라, 분기마다 신고 데이터로 다시 맞춘다.
